このセクションは、ObjectOS を**本番で健全に**保つためのものです。[設定](/docs/configure)がセットアップ時の管理（ユーザー、アクセス、サインイン、連携）を扱うのに対し、*運用*は稼働後の作業を扱います。デプロイメントの堅牢化、監視、何が起きたかの証明、そして問題が起きたときの復旧です。

ここのすべてのページは、セルフマネージドの両エディション、ObjectOS Community と ObjectOS Enterprise を対象としています。両者は同じランタイムを実行するため、運用方法も同じです。ライセンスされた Enterprise イメージがより多くを行う箇所（リリースノートに記載されたダイジェスト、ライセンスキー、複数のレプリカ）では、ページの最後に **Enterprise で追加されるもの** のセクションがあります。ObjectOS Cloud では、私たちがデプロイメントを運用します。

## 運用のページ [#operations-pages]

| ページ | 用途 |
|---|---|
| [本番環境への準備](/docs/operate/production) | 本番稼働の前後にデプロイメントを堅牢化する |
| [オブザーバビリティ](/docs/operate/observability) | ログ、リクエスト id、メトリクス、エラーを接続する |
| [監査ログ](/docs/operate/audit-logs) | 改ざんできない監査証跡と診断ログを読む |
| [バックアップ](/docs/operate/backup) | バックアップと災害復旧を計画する |
| [アップグレード](/docs/operate/upgrade) | 安全にアップグレードまたはロールバックする |
| [トラブルシューティング](/docs/operate/troubleshooting) | 壊れたデプロイメントを診断する |

## 設定と運用の違い [#configure-vs-operate]

セットアップ時の管理（ユーザーの追加、アクセスの付与、メール、ストレージ、連携の接続）は[設定](/docs/configure)にあります。デプロイメントが稼働し、監視、監査、バックアップ、アップグレードが必要になったら、ここに戻ってきてください。
