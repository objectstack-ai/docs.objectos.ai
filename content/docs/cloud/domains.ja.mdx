ObjectOS Cloud の環境には、2 種類のアドレスでアクセスできます。

| | **プラットフォームのサブドメイン** | **独自のドメイン** |
|---|---|---|
| 見た目 | プラットフォームのドメイン上の `acme` | `app.acme.com` |
| プラン | Free を含むすべてのプラン | Team 以上 |
| 環境 | 本番。開発環境は固定のアドレスのまま | 本番のみ |
| 数 | いくつでも追加できます | Team では本番環境ごとに 1 つ。契約によりそれ以上 |
| 証明書 | プラットフォーム自身のものでカバーされます | 所有が証明されると発行されます |

このページのルールは、[cloud#1087](https://github.com/objectstack-ai/cloud/issues/1087)（プラットフォームのサブドメインはすべてのプランで無料）と [cloud#2136](https://github.com/objectstack-ai/cloud/issues/2136)（独自のドメイン）で決定されました。

## プラットフォームのサブドメイン [#platform-subdomains]

本番環境のアドレスは、プラットフォームのドメイン上の組織の[スラッグ](/docs/cloud/organization#the-organization-slug)です。これはすべてのプランで無料で、自分で選ぶほかのブランド付きのラベルも同じく無料です。

変更するには、環境の **Settings → Name and domain** を開き、**Change Hostname** を選びます。ラベルだけを入力します。プラットフォームのドメインは自動で付きます。ラベルは 4〜63 文字の小文字、数字、ダッシュで、両端にダッシュは使えず、2 つ続けることもできません。いくつかの予約語は拒否されます。組織のスラッグで始まる必要はありません。

最初のものを置き換えるのではなく 2 つ目のプラットフォームのサブドメインを追加するには、同じセクションの **Add Domain** を使います。環境の **Overview** に表示されるアドレスが、人に伝えるべきアドレスです。

## 独自のドメイン [#your-own-domain]

**Team** 以上では、本番環境は、`app.acme.com` のような、所有するドメインのサブドメインでも応答できます。

1. **追加します。** **Settings → Name and domain** で **Add Domain**（または **Change Hostname**）を選び、完全なホスト名を入力します。サブドメイン（少なくとも 3 つのラベル）でなければなりません。`acme.com` のようなルートドメインは拒否されます。`www.acme.com` などのサブドメインを使ってください。
2. **所有を証明します。** ドメインは **Pending Verification** として作成され、コンソールに公開すべき TXT レコードが表示されます。名前は `_objectos-challenge.<your hostname>` で、値はこのドメインに固有のものです。ホスト名が向けるべき CNAME のターゲットも表示されます。
3. **確認します。** TXT レコードを公開したら、ドメインで **Verify DNS** を選びます。ObjectOS Cloud はレコードを確認し、それから証明書を要求します。ドメインは **Verified** と **Provisioning Certificate** を経て **Active** になります。途中のステップで止まった場合は、もう一度 **Verify DNS** を選んで先に進めます。
4. **プライマリにします**（省略可能）。**Set as Primary** は、サインインのリダイレクト、メールのリンク、共有リンクがどのアドレスを使うかを決めます。プラットフォームのサブドメインも並んで機能し続けます。

セッションは 1 つのアドレスに属します。プラットフォームのサブドメインと独自のドメインを切り替えると、もう一度サインインすることになります。

### うまくいかないとき [#when-something-goes-wrong]

| 表示されるもの | 理由と対処 |
|---|---|
| `403 CUSTOM_DOMAIN_PLAN_LOCKED` | 組織が Free です。Team にアップグレードしてください。 |
| `403 DEV_ENV_DOMAIN_LOCKED` | これは開発環境です。ドメインは本番環境に追加してください。 |
| www またはサブドメインを求める `400 INVALID_FORMAT` | ルートドメインを入力しました。`www.acme.com` のようなサブドメインを使ってください。 |
| `403 CONTACT_SALES_PLAN` | 環境はすでに 1 つのドメインを持っています。複数持つには Enterprise の契約が必要です。 |
| `409 DUPLICATE_VALUE` | 別の環境がすでにそのホスト名を提供しています。 |
| 確認の応答が、TXT レコードがまだ見えないと言う | DNS が伝播していないか、レコードの名前または値が異なります。応答には期待されるレコードが繰り返し示されます。 |
| **Failed** | 証明書を発行できませんでした。CNAME を確認し、もう一度 **Verify DNS** を選んでください。まず所有を証明し直します。 |

### ダウングレードとアップグレード [#downgrade-and-upgrade]

ダウングレードは独自のドメインを**一時停止**します。決して解放はしません。ドメインは **Suspended** になって提供を止め、証明書は取り下げられますが、レコードは残ります。それがプライマリだった場合、リンクは影響を受けないプラットフォームのサブドメインにフォールバックします。後でアップグレードすると、CNAME がまだ私たちを向いていれば、ドメインは自動的に再プロビジョニングされます。「N 日後に解放」というものはありません。

一時停止されたドメインが、そのホスト名の所有を証明できるほかの誰かを妨げることはありません。別の環境がそれを証明すれば、一時停止されていた主張は放棄されます。

### ドメインを削除する [#removing-a-domain]

ドメインの **Delete** は提供を止め、ホスト名を解放します。環境を完全に削除すると、そのすべてのドメインもあわせて削除されます。
