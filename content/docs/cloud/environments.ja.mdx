**環境**は、独自のデータベース、ファイル、アプリ、アドレスを持つ、ObjectOS の稼働中のコピー 1 つです。組織のアプリは環境の中にあり、チームはそれを使うために環境にサインインします。

**すべての組織は、どのプランでもちょうど 1 つの環境を持ちます。** それが本番環境です。組織をセットアップするときに作成する最初の環境（[ObjectOS Cloud で始める](/docs/start/cloud)）であり、唯一の環境です。1 つの組織、1 つの環境、多数のアプリ。必要なだけのアプリを、その中にインストールし、構築します。

| | **環境** |
|---|---|
| 数 | どのプランでも、組織ごとにちょうど 1 つ |
| アドレス | プラットフォームのドメイン上の組織のスラッグ。Team 以上では[独自のドメイン](/docs/cloud/domains)を付けられます |
| アイドル | 非アクティブによるアーカイブは決してされません |
| 用途 | チームが使うアプリ |

2 つ目の環境は作成できません。プランの違いは、環境が何を保持し、何を許可するか（[ストレージ](/docs/cloud/storage-and-limits)、[AI 利用枠](/docs/cloud/ai-credits-and-limits)、独自のドメイン）にあり、環境の数にはありません。

## 複雑なアプリを開発する [#developing-a-complex-app]

AI Builder とコンソールで足りないアプリは、2 つ目の環境ではなくソースレベルで開発します。`os dev` でローカルに構築して Git で管理し、[パッケージとして公開してインストール](/docs/cloud/apps#deploy-from-the-cli)します。流れ全体は[アプリ](/docs/cloud/apps)を参照してください。

## 環境を作成する [#create-the-environment]

**Environments** で **Create Environment** を選び、名前を付けます。アドレスはプラットフォームが割り当てます。アドレスは後から **Change Hostname**（[ドメイン](/docs/cloud/domains)）で変更できます。新しい環境は **Provisioning** で始まり、データベースの準備ができると **Active** になります。

環境に入るには **Open** を選びます。新しいタブで環境自身のコンソールが、あなたとしてサインインした状態で開きます。

## 環境のページ [#the-environment-page]

各環境には、2 つのタブを持つページがあります。

- **Overview**：アドレス、ステータス、プランと種類、インストールされているアプリ、アクセスの設定。折りたたまれた **Features that need a higher plan** の行は、現在のプランに含まれていないものを数え、開くとその一覧を表示します。
- **Settings**：すべてのアクションが 5 つのセクションにあります。**Apps**、**Plan and billing**、**Name and domain**、**Access and sign-in**（[AI エージェントのアクセス](/docs/configure/mcp#on-objectos-cloud)を含む）、**Lifecycle and danger zone** です。

環境を変更するアクションは、組織のオーナーと管理者に提示されます。

## ライフサイクル [#lifecycle]

| 状態 | 意味 | データ |
|---|---|---|
| **Active** | リクエストを処理しています | — |
| **Suspended** | 再開するまで、ランタイムへのすべてのトラフィックがブロックされます | 保持されます |
| **Archived** | アクティブな表示から外され、訪問されても起動しなくなります | 誰かが削除するまで保持されます |
| **Failed** | プロビジョニングが完了しませんでした | 何も作成されていません |

**一時停止と再開。** 一時停止すると、人からも連携からも、環境へのすべてのリクエストがブロックされます。何も削除されず、**Resume** で元どおりに戻ります。

**アーカイブと復元。** アーカイブすると、環境は使われなくなります。**Restore** はデータとともに環境を戻し、次の訪問で再び起動します。

**削除。** 削除は 2 段階の操作なので、1 回のクリックでデータが失われることは決してありません。

1. まだアーカイブされていない環境は、完全な削除を求めた場合でも**アーカイブ**されます。
2. **アーカイブ済み**の環境を、**Delete permanently if already archived** にチェックを入れて削除すると、そのデータベースとすべてのファイルが一度に破棄され、復旧はできません。

本番環境を削除するときは、さらに **Force-delete the production environment** にチェックを入れるよう求められます。プロビジョニングに失敗した環境はデータを持たないので、即座に削除されます。

### アーカイブされた環境がどれだけ保持されるか [#how-long-an-archived-environment-is-kept]

アーカイブされた環境は、データベース、ファイル、ドメインとともに、誰かが削除するまで保持されます。どのプランでも、タイマーで期限が切れることはありません。アーカイブするのは常にあなたの選択で、削除も同じです。データを破棄するのは、上に書いた明示的で完全な **Delete** だけです。
