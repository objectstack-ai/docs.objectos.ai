在 ObjectOS Cloud 上，你拥有的一切都属于一个**组织**：它的环境、它的应用和
包、它的套餐和它的成员。你在注册时创建它（[在 ObjectOS Cloud 上开始](/docs/start/cloud)），
并在 [cloud.objectos.ai](https://cloud.objectos.ai) 的**云控制台**中管理它。

## 云控制台 [#the-cloud-console]

控制台的侧边栏就是本节的地图：

| 侧边栏项 | 包含什么 | 页面 |
|---|---|---|
| **Home**（首页） | 组织一览：生产环境、应用、成员、本周的 AI 额度 | — |
| **Environments**（环境） | 每个环境，及其设置和生命周期 | [环境](/docs/cloud/environments) |
| **Members**（成员） | 组织中的人员及其待处理的邀请 | 本页 |
| **Billing**（账单） | 套餐对比，以及升级 | [套餐与 AI 席位](/docs/cloud/plans-and-seats) |
| **Advanced → Connected Runtimes** | 关联到这个组织的自托管服务器 | [云连接](/docs/cloud/cloud-connection) |
| **Advanced → Packages** | 你的组织已发布的包 | [应用](/docs/cloud/apps) |

每个环境也有自己的控制台，位于该环境自己的地址。你的团队在那里使用应用；
云控制台则是你管理应用所在组织的地方。

## 组织 slug [#the-organization-slug]

**slug** 是组织的简短标识符，在注册时选定。它也是你的生产环境的地址：
slug 后面跟上平台的域名。

- 4 到 30 个字符：小写字母、数字和短横线。
- 开头和结尾不能是短横线，也不能有两个连续的短横线。
- 一小部分保留字会被拒绝（`admin`、`api`、`www`、`docs`、
  `default`，以及平台自己使用的其他词）。

所有者或管理员可以在组织的记录上用 **Change Slug** 修改 slug，每 90 天
最多一次。组织的每个平台子域名都会改写为新的 slug，旧的 slug 会被保留 90
天，以免在此期间被其他人占用。你自己的域名
（[域名](/docs/cloud/domains)）不受 slug 变更影响。

## 成员与邀请 [#members-and-invitations]

打开侧边栏中的 **Members**。这个页面有两个标签页：成员及其角色，以及仍待
处理的邀请。

要添加某人，选择 **Invite members**，输入对方的电子邮件地址并选择一个
角色。对方会收到一份邀请，接受之后就成为组织的成员。

**组织的邀请是进入其环境的唯一途径。** 环境没有自己的邀请，也没有自助
注册：你在这里邀请的每个人都能进入组织的环境，而他们在某个环境中能做
什么，由该环境的[权限](/docs/configure/permissions)决定。

在这些列表中，管理组织的人可以**更改成员的角色**、**移除成员**，以及
**重新发送**或**撤销**待处理的邀请。

## 角色 [#roles]

成员角色决定一个人在组织中能触及什么。它不是权限集：某人在环境中能对记录
做什么，来自该环境的[权限集和岗位](/docs/configure/permissions)。

| 角色 | 用途 | 谁能邀请此角色 |
|---|---|---|
| **Owner**（所有者） | 完全控制组织、它的套餐和它的环境 | 所有者 |
| **Admin**（管理员） | 管理组织：成员、环境、账单 | 所有者或管理员 |
| **Delegated Admin**（委派管理员） | 无需是管理员即可访问邀请端点；能把人放到哪里，取决于另行授予的管理范围 | 所有者或管理员 |
| **Member**（成员） | 使用组织的环境和应用 | 任何能发出邀请的人 |
| **External**（外部用户） | 门户用户 —— 供应商或客户的人员 —— 只能看到自己的行以及明确共享给他们的内容；从不属于业务单元树 | 任何能发出邀请的人 |

所有者和管理员就是本节所说的"管理组织的人"：他们能看到套餐、升级以及
会改变某些东西的环境操作。普通成员能看到环境并打开它们，但不会看到他们
无法完成的操作。

## 登录在哪里进行 [#where-sign-in-lives]

在 ObjectOS Cloud 上，每个账户都是云账户。由 ObjectOS Cloud 让人登录，环境
接收他们：环境为每个人保存的**只有授权** —— 他们的岗位、权限集和共享。
每个托管环境默认都使用这一个登录，在每个套餐上都是如此，因此人们用
ObjectOS Cloud 账户登录一次，就能在各个环境之间切换。

**把环境迁到你自己的基础设施上。** 因为账户保存在 ObjectOS Cloud 而不是
环境中，它们不会随环境一起迁移。在自管理部署上，你要么在那里为人们签发
新的凭据，要么把它绑定到你自己的身份提供商，让他们通过它登录 —— 参见
[身份认证](/docs/configure/authentication)。
