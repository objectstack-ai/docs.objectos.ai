本章面向 ObjectOS 部署的**系统管理员**：负责用户入职、授予访问权限、接通登录、邮件、存储与集成，并保持系统健康运转的人。你日常管理的是人和他们的权限；应用、对象和权限集本身则随平台及你安装的应用包一起交付。

## Setup 与 Studio [#setup-and-studio]

**权限在 Studio 中设计，在 Setup 中分配。** 这句话是对一条贯穿整个产品的划分的标准表述，而不只是关于权限的规则：Setup *运营*一个运行中的部署，Studio *编写*这个部署所运行的元数据。两者都位于 `/_console/` 下的同一个 UI 中；谁都不是独立的界面。

| | Setup | Studio |
|---|---|---|
| 回答 | 谁在这里，他们可以做什么？ | 这个应用由什么组成？ |
| 位置 | `/_console/apps/setup` | `/_console/studio` |
| 门控 | `setup.access` | `studio.access` |
| 面向 | 系统管理员 | 实施人员和开发者 |

绝大多数管理工作都不会离开 Setup —— 只有编写权限集或运行解释引擎时才需要进入 Studio。

## Setup 应用 [#the-setup-app]

内置的管理应用位于 **`/apps/setup`**，需要 `setup.access` 权限。其左侧导航由运行时已加载的能力插件动态提供，因此你看到的菜单精确反映当前部署所运行的内容——未启用的能力不贡献任何菜单项，其分组保持为空。

稳定的导航分组：

| 分组 | 里面有什么 |
|---|---|
| **Overview**（概览） | System Overview 系统概览仪表盘 |
| **People & Organization**（人员与组织） | 用户、业务单元、团队、组织、邀请 |
| **Access Control**（访问控制） | 岗位、权限集、共享规则、记录共享、API Key |
| **Approvals**（审批） | 审批流程（加载 approvals 插件时） |
| **Configuration**（配置） | 全部设置、品牌、认证、邮件、文件存储、AI 与 Embedder、知识库、功能开关 |
| **Diagnostics**（诊断） | 会话、通知事件、审计日志 |
| **Integrations**（集成） | Webhooks |
| **Advanced**（高级） | OAuth 应用、签名密钥（JWKS）、身份关联、用户偏好 |
