ObjectOS is one product in three editions. **ObjectOS Community** is the
open-source runtime you run yourself. **ObjectOS Cloud** is the same product
hosted for you, on the **Free** and **Team** plans. **ObjectOS Enterprise** is
the licensed product on your own infrastructure: one edition, always a
private deployment, sold by contract and priced per AI user. ObjectOS Cloud
has no Business plan and no Enterprise plan. Prices and contracts are on
[License & Pricing](/docs/editions/license); this page is what each one does
differently.

Every page in these docs carries a row of edition badges under its title,
naming the editions it applies to. The sidebar marks the pages and groups that
are not for every edition with the same icons.

## The matrix

| | **Community** | **Cloud Free** | **Cloud Team** | **Enterprise** |
|---|---|---|---|---|
| Delivery | Self-managed | Hosted | Hosted | Self-managed |
| Price | Free (Apache-2.0) | Free | $24 / AI seat / month, or $20 / AI seat / month billed annually | By contract, per AI user, 25 minimum: contact sales |
| File storage | Your own ([Storage](/docs/configure/storage)) | 1 GB per environment | 20 GB per environment | Your own ([Storage](/docs/configure/storage)) |
| Environments | As many as you deploy | One per organization | One per organization | As many as you deploy |
| MCP requests | Set by your deployment | 20 / minute, 1,000 / day | 120 / minute, no daily cap | Set by your deployment |
| Custom domain | Your own host | — | — | Your own host |
| Record- and field-level security | ✓ | ✓ | ✓ | ✓ |
| Approval workflows | ✓ | — | ✓ | ✓ |
| Scheduled and time-relative flows | ✓ | — | ✓ | ✓ |
| In-UI AI (AI Builder, "ask your data") | MCP only — bring your own model | Taste | ✓ | ✓ |
| AI governance (action audit, guardrails, permission scoping) | — | — | — | ✓ |
| Single sign-on with your identity provider | ✓ ([Authentication](/docs/configure/authentication)) | — | — | ✓ |
| SCIM 2.0 provisioning | Open, off by default (`OS_SCIM_ENABLED`) | — | — | On by default |
| Several organizations on one deployment | Open source in the framework, not in the Community image ([Multi-organization](/docs/deploy/multi-organization#on-the-community-image)) | — | — | ✓ |
| High availability (several replicas) | — | — | — | In development, not offered yet |
| Air-gapped operation | — | — | — | ✓ |
| Support | Community | Community | Standard | Standard; priority and SLA support by contract |

There is no Enterprise edition on ObjectOS Cloud: Enterprise is always a
private deployment on infrastructure you operate. An Enterprise license
includes every Enterprise feature, whatever the size of the deployment.
Single sign-on with your identity provider and several organizations on one
deployment are open source, free on a self-managed deployment; an Enterprise
license adds our support for them. A deployment runs on one node today, with
backup and restore; high availability across several replicas is in
development and is not offered until it ships. On a self-managed
deployment, Community and Enterprise run the same runtime: everything in the
Community column is in the Enterprise column too.

## Where each difference is enforced

The matrix lists only differences the product enforces. These are the ones
these docs already describe in detail:

- **The license decides what a self-managed deployment is.** Without one, a
  single-organization deployment runs with Community behaviour — the open MCP
  server, bring your own AI. With one, the AI Builder and "ask your data" are
  unlocked on your own infrastructure. See [AI Service](/docs/configure/ai).
- **On the Enterprise image, several organizations need the license.** A
  multi-organization posture without one is refused at startup, and the runtime
  does not serve traffic. The multi-organization runtime itself is open
  source; the Community image does not ship it. See
  [Multi-organization](/docs/deploy/multi-organization),
  [Runtime Configuration](/docs/configure/runtime) and
  [Troubleshooting](/docs/operate/troubleshooting).
- **Air-gapped operation is a license mode.** An ordinary license is validated
  online against a control plane; an air-gap license is verified locally, and
  the deployment must also declare no control plane. The combinations that
  cannot work are refused at startup. See
  [Air-gapped Deployment](/docs/deploy/air-gapped).
- **On ObjectOS Cloud, the plan is enforced per environment.** An
  organization has one environment on every plan; a full
  environment refuses attachment uploads and bulk imports, never single-record
  writes, reads or exports (`403 STORAGE_LIMIT_REACHED`, with a warning from
  80%); and the MCP endpoint answers `429` past the plan's request limit. See
  [Environments](/docs/cloud/environments) and
  [Storage and Limits](/docs/cloud/storage-and-limits).
- **An ended subscription falls back to Community.** The Enterprise features
  switch off, and the system and its data keep working. Keeping a version
  after the end, a version lock, comes only with a perpetual license bought
  outright by contract. Three configurations that need a license refuse to
  start instead. See [Licensing](/docs/deploy/licensing#when-a-license-ends).

## Which edition is this page for?

| Badge | Means |
|---|---|
| Community | True when you run ObjectOS Community yourself |
| Cloud | True on ObjectOS Cloud, on the Free and Team plans |
| Enterprise | True on a licensed, self-managed ObjectOS Enterprise deployment |

Deploy and Operate are for the two self-managed editions, Community and
Enterprise: on ObjectOS Cloud we run the deployment for you.
